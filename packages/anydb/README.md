# AnyDB

Covers AnyDB two ways. With an API key it uses AnyDB's integration API: validate credentials, list teams and databases, list, search, read, create, update, copy and remove records, upload and download files, create shares, and register, subscribe and manage webhooks (20 tools, 13 of them mutations that require approval). With OAuth it uses AnyDB's official hosted MCP server, which the vendor documents as 56 tools covering records, search and access, files, workspaces and types, views, sharing and reports, and workflows.

**Interface:** OpenAPI plus remote MCP.
- OpenAPI: AnyDB's own "Ext Integration API" document, https://www.anydb.com/openapi/spec.yaml (Swagger UI at https://www.anydb.com/openapi, linked from https://www.anydb.com/support/integrations/api). Requests go to `https://app.anydb.com`. The spec has no `operationId`s, so tool names are generated from paths.
- MCP: https://mcp.anydb.com (docs: https://www.anydb.com/support/integrations/anydb-mcp/). Tools come from the server; any tool without `readOnlyHint` requires approval.

**Auth:**
- API key: the REST API needs two headers, `x-anydb-api-key` and `x-anydb-email`, so the account asks for both the integration key and the email of the AnyDB user it belongs to. Get the key from the Profile dialog, Integration tab, in AnyDB (see https://www.anydb.com/support/integrations/typescript-sdk). The key grants access to whatever that user can see. The health check calls `checkauth`, a POST, which the framework classes as a mutation, so calling that tool by hand prompts for approval even though it only checks credentials.
- OAuth: `oauth2({ discover: "https://mcp.anydb.com" })`. The server publishes protected-resource metadata pointing at the issuer `https://app.anydb.com/oauth`, whose metadata (`/oauth/.well-known/oauth-authorization-server`) advertises dynamic client registration (`/oauth/reg`) and PKCE S256, so no pre-registered OAuth app is needed. Scopes are left to the server's metadata (`mcp:read`, `mcp:write`, `mcp:author`), because the docs do not list them. The redirect URI is the one Executor shows when connecting.

**Known gaps:** The MCP tools are only available to OAuth accounts; API-key accounts only get the 20 REST tools (no workspace, type, view, report or workflow operations, since the REST spec lacks them). The MCP 401 challenge says "Provide an OAuth bearer token, or x-anydb-api-key with x-anydb-email", which suggests the MCP server may also accept the API-key headers. The vendor docs say nothing about that (they describe OAuth as the hosted method), and it was not tested because no real credentials may be used, so it is not wired up. `scripts/mcp-probe.ts` was fixed to resolve authorization-server metadata under the issuer path; before that it misread this server.
