# SAP SuccessFactors

Employee Central people, employment, job and compensation data, foundation objects (companies, departments, cost centers, positions) and Recruiting (requisitions, applications, candidates) for one SuccessFactors tenant, plus generic access to any OData entity.

**Interface:** hand-written tools over SAP's OData v2 API, `https://{apiServer}/odata/v2/...` (official, documented in the SAP SuccessFactors "HXM Suite OData API" reference on help.sap.com). SAP publishes per-module OpenAPI/EDMX documents only through the login-gated Business Accelerator Hub, and the entity model differs per tenant (custom `cust_*` MDF objects), so nothing can be compiled ahead of time. Named list tools cover common entities; `entities.list/get/create/update/delete/upsert/metadata` reach any entity set the API user may access. All writes require approval. Tool paths follow the documented OData v2 conventions and were not exercised against a live tenant.

**Auth:** two methods, both against the data-center API server shown in the SAP API server list (for example `api10.successfactors.com`; `*.successfactors.com/.eu/.cn` and `*.sapsf.*` are accepted).
- API user (basic authentication): company ID, a username and password sent as `username@companyId`. In Admin Center create a dedicated API user and a permission role granting "Allow Admin to Access OData API through Basic Authentication" (under Manage Integration Tools) plus the data permissions you need. Basic authentication also requires the caller's IP to be allowed: add it in Admin Center under "OData/REST API Basic Authentication Configuration", or set a per-user API login exception. Without these, requests fail with 401/403. SAP is retiring basic authentication for APIs (see "Deprecation of Basic Authentication for APIs", SAP release information): it becomes off by default in 1H 2027 with an opt-in, and is deleted on 12 Nov 2027. Plan to move to OAuth.
- OAuth access token: a bearer token you mint outside Executor and paste in. SAP's OAuth route is the SAML 2.0 bearer grant: register an X.509 certificate under Admin Center "Manage OAuth2 Client Applications", then POST a signed SAML assertion to `https://{apiServer}/oauth/token` with `grant_type=urn:ietf:params:oauth:grant-type:saml2-bearer`. The token is used as-is, is not refreshed, and expires (see `expires_in`), so you must paste a new one when it does.

**OAuth gap (accepted):** Executor does not mint the SAML-bearer token in-app. That needs a signed XML assertion built from your private key, which the account form cannot do, so the token must come from an external generator. SuccessFactors has no documented browser authorization-code flow, so no `oauth2` method is offered.

**Known gaps:** OData v4 services (calibration, continuous feedback, nominations), the SOAP/SFAPI interface and Learning/Onboarding APIs on separate hosts are not wrapped. Which entities respond depends on the API user's permissions. Icon: SAP's official logo (SuccessFactors is an SAP product and has no separate public mark).
