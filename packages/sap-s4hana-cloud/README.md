# SAP S/4HANA Cloud

Business partners (customers, suppliers), sales orders, billing documents, deliveries, purchase orders, supplier invoices, products, material documents and production orders for one S/4HANA Cloud tenant, plus generic access to any OData v2 service.

**Interface:** hand-written tools over SAP's released OData v2 APIs at `https://{apiServer}/sap/opu/odata/sap/...` (API_BUSINESS_PARTNER, API_SALES_ORDER_SRV, API_PURCHASEORDER_PROCESS_SRV, API_PRODUCT_SRV and others, documented on SAP Business Accelerator Hub, api.sap.com). SAP's per-API OpenAPI/EDMX documents sit behind that hub, and the available services differ per tenant and communication arrangement, so nothing is compiled ahead of time. The `odata.*` tools (list, get, metadata, create, update, delete, callFunction) reach any service path, including custom BTP applications. Writes fetch an X-CSRF-Token from the service root first and require approval. Updates and deletes send `If-Match` with the optional `etag` input, or `*` when omitted. Tool paths follow the documented conventions and were not exercised against a live tenant.

**Auth:** two methods, both against your API server host (for example `my300000-api.s4hana.cloud.sap`, or a BTP host such as `my-app.cfapps.eu10.hana.ondemand.com`).
- Communication user (basic authentication): in S/4HANA Cloud create a communication system and user, then a communication arrangement for each scenario you need (for example SAP_COM_0008 for Business Partner, SAP_COM_0109 for Sales Order). Enter the API server, the communication user name and its password.
- OAuth 2.0 client credentials: for APIs fronted by SAP BTP (XSUAA). From the service key take the `clientid` and `clientsecret`, and the subdomain and region of the authentication URL `https://<subdomain>.authentication.<region>.hana.ondemand.com` (China regions such as `cn40` use `platform.sapcloud.cn`). Executor requests a token from `/oauth/token` using HTTP Basic client authentication and sends it as a bearer token. The token is requested again on each run; there is no refresh token. S/4HANA Cloud public-edition communication arrangements can alternatively use the tenant's own OAuth 2.0 endpoint; that is not covered here. Host patterns match one DNS label, so the multi-label BTP hosts are listed per region; a region missing from the list in `index.ts` is rejected.

No browser OAuth flow is offered: the token URL depends on your subdomain and region, so the client credentials are entered in the account form.

**Known gaps:** Only communication arrangements you have created expose their APIs, so some named tools may return 403 or 404. The health check for a client-credentials account is a successful token request; for a communication user it calls API_BUSINESS_PARTNER and accepts 403 or 404 as proof the user authenticated (401 or other errors fail). SOAP and OData v4 services are not wrapped except through the generic tools. Icon: SAP's mark from Simple Icons.
