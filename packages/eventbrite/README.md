# Eventbrite

Events, ticket classes and groups, orders, attendees, venues, discounts, checkout questions, teams, reports, webhooks and reference data (categories, formats, fee rates) from the Eventbrite API v3.

**Interface:** hand-written tools over the official REST API at `https://www.eventbriteapi.com/v3` (reference: https://www.eventbrite.com/platform/api). Eventbrite publishes no OpenAPI document and no remote MCP server. It does publish an official API Blueprint file (`eventbrite-api-v3-public.apib`, https://www.eventbrite.com/platform/new/docs/eventbrite-api-v3-public.apib); it is not OpenAPI and Executor cannot consume it directly, so it was used as the reference for the hand-written tools instead. The only OpenAPI documents found are third-party generated ones, which are not used. Paths, parameters and body shapes were checked against the `.apib` (including discounts `scope` enum `event|multi_events|user`, `ticket_buyer_settings` envelope, `get_retention_policy_information`, and `pricing/calculate_price_for_item` body with `base_price`, `country`, `scope`). Path IDs are URL-encoded; `.` and `..` are rejected. Tools are grouped by resource (`events`, `ticketClasses`, `orders`, `attendees`, `venues`, `discounts`, `questions`, `reports`, `webhooks`, `teams`, `users`, `organizations`, `reference`). Request bodies for create and update calls are passed as JSON objects and wrapped in Eventbrite's envelope (`{ "event": ... }`) by the tool. List calls take a `continuation` token for the next page. Start with `users.organizations` to find the organization ID most tools need. Every mutation requires approval.

**Auth:**
- Private token (`token`): create it in your Eventbrite account under Account Settings, Developer Links, API Keys (https://www.eventbrite.com/platform/api-keys). Sent as `Authorization: Bearer <token>` to `www.eventbriteapi.com` only (confirmed in the `.apib` Authenticate API Requests section).
- OAuth (`oauth`): create an app at https://www.eventbrite.com/platform/api-keys and enter its API key as the client ID and its client secret in the connect page. Register Executor's OAuth redirect URI as the app's OAuth redirect URI. Authorization URL `https://www.eventbrite.com/oauth/authorize`, token URL `https://www.eventbrite.com/oauth/token`. The `.apib` confirms the token request is a form POST with `client_id`, `client_secret`, `code`, `redirect_uri` and `grant_type=authorization_code` in the body (client_secret_post). Eventbrite OAuth has no scopes and tokens do not expire.

**Known gaps:** the remaining-balance endpoint (`/balance/{org}/events/{event}/`) is omitted because the `.apib` serves it from separate balance-api hosts, not `www.eventbriteapi.com`; ticket group to ticket class attach, team search and password check, and seat map creation for an event are not exposed; the health check does not report a display name because the user `name` nullability is not documented in the `.apib`; the public event search endpoint (`/events/search/`) was shut down by Eventbrite in 2019 and is not exposed; the deprecated global webhook endpoints are omitted in favour of the organization-scoped ones. Media upload (multi-step, binary), text overrides, seat map copy, canned question edits, inventory tier writes and team creation are not exposed.

**Icon:** Eventbrite's orange "e" app icon, from the official site's `android-chrome-192x192.png` (https://www.eventbrite.com). Simple Icons has no Eventbrite entry.
