# TomTom

Location APIs from TomTom: fuzzy, POI, category, geometry, nearby and along-route search, POI categories, geocoding (including structured and premium geocoding) and reverse geocoding (`search`), route calculation (`routing`), and raster and vector map tiles, map assets, static images, copyrights, WMS and WMTS (`maps`). 36 tools in total.

Interface: OpenAPI plus the official remote MCP server. The OpenAPI documents are TomTom's own API Explorer files from https://docs.tomtom.com/assets/openapi/ (`search-api-explorer.yml`, `geocoding_api.yml`, `reverse_geocoding_api.yml`, `routing_api.yml`, `maps_api.yml`). TomTom does not advertise them as downloads, so `scripts/vendor-openapi.ts tomtom` commits them as JSON (`search.json`, `routing.json`, `maps.json`) and records each source URL, its SHA-256 and the retrieval date in `info.x-executor-source`. `search.json` joins the Search, Geocoding and Reverse Geocoding files, which were one Search API before, so those tool names stay the same. POST operations that only compute a result (route calculation, geometry filters, along-route search) run without an approval prompt. The official TomTom Maps MCP server (`https://mcp.tomtom.com/maps`, public preview) is mounted under `mcp`. It adds the traffic flow and incident tools the OpenAPI set lacks, plus multi-stop optimization and static maps. MCP tools prompt for approval unless they declare `readOnlyHint`.

Auth: API key. Create one at https://my.tomtom.com (or the developer portal, https://developer.tomtom.com) and enable the MCP Server product (or tick "All") plus Map Display, Routing, Search, Geocoding, Reverse Geocoding and Traffic. Per TomTom's quick-setup doc, the key goes to `api.tomtom.com` as the `key` query parameter (the scheme every TomTom document declares) and to `mcp.tomtom.com` as the `tomtom-api-key` header. The server also advertises OAuth metadata, but the documented method is the API key, so that is the only method offered. The optional `tomtom-maps-backend` header is not set (the server defaults to `tomtom-maps`). The health check makes a one-result geocode request, checks its `summary.numResults`, then connects to the MCP server. It uses one billable request. Neither the key parameter nor the header has been tried with a live key here.

Traffic Analytics MCP: evaluated and excluded. TomTom's Traffic Analytics MCP Server (https://github.com/tomtom-international/tomtom-traffic-analytics-mcp) runs locally and has no hosted endpoint, so Executor cannot mount it. Most of its tools also need a MOVE Portal account and key. Its live traffic flow and incident tools overlap the hosted Maps MCP.

Known gaps:
- TomTom's Routing file has no Calculate Reachable Range operation, though the API itself still documents one. TomTom publishes no OpenAPI description for it, so it is not covered.
- The v1 copyrights endpoints (by bounding box or tile) are not in TomTom's Map Display file. Only the v2 `copyrights` and `copyrights/caption.json` are covered.
- Geofencing, Traffic, EV and the other TomTom APIs have no API Explorer file and are not covered.
- `scripts/tools.ts` compiles only the exported `options` (the Search document, 21 tools), so `scripts/check.sh` does not compile the maps and routing documents.
- Refresh with `node scripts/vendor-openapi.ts tomtom`. If TomTom moves the files, the script fails on the download.
