# Snapchat

Snapchat Ads through the Snap Marketing API: organizations, ad accounts, campaigns, ad squads, ads, creatives, media entities, custom audience segments, targeting option catalogs and performance stats (49 tools). Reads run freely; every create, update and delete asks for approval.

**Interface:** hand-written tools over the Marketing API at `https://adsapi.snapchat.com/v1` (docs: https://developers.snap.com/api/marketing-api/Ads-API/introduction). Snap publishes no OpenAPI document or GraphQL API. Snap does run an official Ads MCP server at `https://mcp.snapchat.com/ads` (read-only, scope `snapads.read`), but it accepts only pre-registered OAuth client IDs with no dynamic client registration, so Executor cannot connect to it; the hand-written Marketing API tools are therefore used, which also allows write tools. Create and update tools take the request `body` as JSON in the shape Snap documents (for example `{"campaigns":[...]}`).

**Auth:** OAuth 2.0. Create an OAuth app in Snap Business Manager (Business Details > OAuth Apps; Organization Admin only), register the Executor redirect URI shown on the connect page, and enter the client ID and secret there. The app requests the `snapchat-marketing-api` scope; tokens last an hour and are refreshed with the refresh token. Client credentials are sent as form fields.

**Access:** Snap may require approval (allowlisting) before an OAuth app can call the Marketing API; older docs say to email dev-support@snap.com with the OAuth client ID. Current pages do not mention it, so request access if calls are rejected.

**Endpoint verification (developers.snap.com, Oct 2026):** Confirmed against the per-resource docs: `/me/organizations` (with `with_ad_accounts`), `/organizations/{id}`, `/organizations/{id}/adaccounts`, `/members`, `/fundingsources`, `/billingcenters`, `/catalogs`, `/pixels`; `/adaccounts/{id}`, `/roles`, `/pixels`, `/stats`; campaigns, ad squads, ads, creatives, media and segments list/get/create (POST)/update (PUT)/delete paths and their `{"campaigns"|"adsquads"|"ads"|"creatives"|"media"|"segments":[...]}` wrappers; stats for ad accounts, campaigns, ad squads and ads (granularity is required by the API, and ad account stats expose only spend); targeting geo/country, geo/{cc}/region, demographics, device, interests and `/targeting/v1/options?country_code=`. Removed because the docs show no such endpoint: ad account members (members are managed through roles). Fixed: ad account pixel is `/adaccounts/{id}/pixels`. Not confirmed: the `{me: {...}}` wrapper of `GET /v1/me` (docs show only the inner object), so the health check relies on it. The `/me` sample lists id and email. `/adaccounts/{id}/media` and the media entity lifecycle are confirmed, but upload endpoints are not exposed. Update tools use PUT, which needs the full object; PATCH (JSON Patch) is not exposed. Targeting `interests/dlxs`, `dlxc`, `dlxp` (stopped 27 Sep 2024) and `interests/plc` are not offered.

**Known gaps:** Conversions API (`tr.snapchat.com`, scope `snapchat-offline-conversions-api`), Public Profile API (`businessapi.snapchat.com`, allowlisted), Ads Gallery, media file upload (multipart), ad previews, and the asynchronous reporting endpoints are not exposed.
