# Paylocity (NextGen)

Paylocity's NextGen (API Hub) integration APIs: employee demographics v2, pay statements, direct deposit bank accounts, earnings, pay entry (Run Payroll batch) imports, Time and Labor cost centers, the three-step company punch detail export, employee punch details, and scheduling shifts (company, employee and open).

**Interface:** 17 hand-written tools over the official API Hub endpoints (`https://dc1prodgwext.paylocity.com/apiHub/...`; `dc1demogwext` for the demo environment). Paylocity publishes no downloadable OpenAPI document: its developer portal (https://developer.paylocity.com/integrations/reference) embeds a definition in each endpoint page only, so the tools were written from those pages. Only these NextGen endpoints were wrapped; the older WebLink API (`/api/v2/...`, different token server) is a separate Paylocity product and is not included. Mutations (`payroll.payEntryImport.create`, `time.punchDetails.createOperation`) require approval.

**Auth:** OAuth 2.0 client credentials. Paylocity issues the client id and secret after it approves an integration request (https://developer.paylocity.com/integrations/docs/getting-started); there is no self-service OAuth app or API key, and no redirect URI. Enter the environment (`production` or `demo`), your Paylocity company id, the client id and the secret. Executor exchanges them at `/public/security/v1/token` and caches the one-hour token. Secrets must be rotated every 365 days. Credentials are only sent to `dc1prodgwext.paylocity.com` and `dc1demogwext.paylocity.com`. The account check only mints a token, since no read endpoint is available to every grant.

**Known gaps:** not wrapped are the partner-restricted APIs (Assessments, Background Check, Learning Management, Partner Onboarding, Pay Details), the Job Code and Document Management endpoints (no per-endpoint definition was published), and webhooks. The employee demographics v2 endpoints are beta and limited to early-adoption customers. Request bodies for the two writes are passed as a JSON `body` per the API reference.
