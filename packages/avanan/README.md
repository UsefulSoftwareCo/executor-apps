# Avanan

Check Point Harmony Email & Collaboration (formerly Avanan): search and inspect security events, search and inspect secured emails, files and messages, run remediation actions on both, check queued action status, and manage allow-list and block-list exceptions. MSP clients can list and scope to every managed tenant.

**Interface:** hand-written tools over the documented Avanan Smart API v1.0 (`https://<region>.avanan.net/v1.0`, reference PDF at https://www.avanan.com/hubfs/MSP/documents/Smart-API-Documentation/master/Avanan_SmartAPI_Reference_Guide.pdf). The vendor mentions a Swagger interface but publishes no OpenAPI document at a stable public URL, and no remote MCP server, so all 13 documented endpoints are wrapped: `scopes.list`, `events.get/search/act`, `entities.get/search/act`, `tasks.get` and `exceptions.list/get/create/update/delete`. Every mutation requires approval.

**Auth:** Client ID (app id) and Secret Key, plus the API region subdomain (`smart-api-production-1-us`, `-1-eu`, `-1-ca`, `-5-ap`, `-1-euw2`, `-1-mec1`, `-1-aps1`). Avanan issues the key pair on request: ask Avanan / Check Point Support, or for MSPs use the MSP key. Credentials are regional. The tools exchange them for a token (the guide says valid 24 hours; the tools cache it for 50 minutes and, on a 401, drop it and retry once) via `GET /auth` and sign every request with `x-av-sig` (SHA-256 of the base64 of request id, app id, date, endpoint and secret key), as documented. There is no OAuth.

**Icon:** the pink umbrella mark from the Avanan logo on the cover of the vendor-published Smart API Reference Guide PDF (raster, cropped at 300 ppi and scaled to 256px). Avanan.com now redirects to Check Point, and the Harmony product logo on checkpoint.com is a wordmark only, so the guide is the only official source of the Avanan mark.

**Known gaps:** the token response shape was implemented from the PDF and could not be exercised without real credentials. The signature endpoint text is the full path including /v1.0 (the guide: "/v1.0/event/<event_id>", "/v1.0/search/query"). The x-av-date value is ISO 8601 with milliseconds and Z, exactly as in every example in the guide; the same string is sent and signed. Available entity/event action names are listed by the API (`events.get` returns `availableEventActions`); entity action names such as quarantine are not enumerated in the guide.
