# ServiceNow

Incidents, problems, change requests and tasks, service requests and the service catalog, CMDB configuration items and relations, knowledge articles, users and groups, attachments, import sets, email, aggregates, and any table of a ServiceNow instance.

**Interface:** hand-written tools over ServiceNow's REST APIs, about 111 in total. ServiceNow publishes no OpenAPI document at a public URL (each instance can export its own, but that needs an account), and its APIs live on a per-instance host, so the tools are written against the vendor's REST API reference (https://www.servicenow.com/docs/ , "REST API reference"): Table API (`/api/now/table`, with generic `table.*` tools plus typed ones for incident, problem, task, sc_request, sc_req_item, sc_task, sys_user, sys_user_group, sys_user_grmember, cmn_location, core_company, cmn_department, cmdb_ci, cmdb_ci_server and kb_knowledge), Aggregate API (`/api/now/stats`), Change Management API (`/api/sn_chg_rest/change`), Service Catalog API (`/api/sn_sc/servicecatalog`), CMDB Instance API (`/api/now/cmdb/instance`, `/api/now/cmdb/meta`), Knowledge Management API (`/api/sn_km_api/knowledge`), Attachment API, Import Set API, Email API, and a table `schema` tool that reads `sys_dictionary` through the Table API. A `rest` tool reaches any other endpoint under `/api/` (scripted REST APIs and so on). Every mutation asks for approval first. The Change Management, Service Catalog and Knowledge APIs need their plugins active and the user's roles.

**Why not ServiceNow's MCP server:** ServiceNow now ships an official MCP Server (`sn_mcp_server`, generally available, OAuth 2.1, Streamable HTTP, licensed through AI Gateway). It is not used because the endpoint is per instance (there is no single vendor URL to declare, and the framework takes static URLs), and an instance admin must provision the server and publish each tool (Now Assist skills, subflows, actions, scripted REST) before anything is exposed, so the tool set differs for every customer. The hand-written REST tools work on any instance with just a user and password.

**Verification against vendor docs:** checked on the official REST API reference: Table, Aggregate (`sysparm_order_by`), Attachment, Import Set, Email API (`POST /api/now/email`, fields to/cc/bcc/subject/text/html/table_name/table_record_id; needs the `email_api_send` role), CMDB Instance API including `POST .../relation` and `DELETE .../relation/{rel_sys_id}`, CMDB Meta API (`/api/now/cmdb/meta/{className}`), Service Catalog, Knowledge, and Change Management (`GET/POST /change`, `/change/normal`, `/change/emergency`, `/change/standard/{template}` and `/change/standard/template`, `/change/model`, `/{sys_id}/conflict`, `/{sys_id}/task`). The undocumented approvals GET was removed (the API only documents changing approvals). Nothing was called against a real instance.

**Auth:** username and password (HTTP basic), sent only to `*.service-now.com`. Enter the instance (the `acme` in `acme.service-now.com`, or the full host; anything else is rejected), a user name and its password. Use a dedicated integration user with the roles the tools need (for example `itil` and `rest_api_explorer`), and enable "Web service access only" on it. The health check looks the user up in `sys_user` and requires exactly one row; user names are limited to letters, digits, `.`, `_`, `-` and `@`.

**Known gaps:**
- No OAuth. ServiceNow supports OAuth (authorization code, client credentials, JWT bearer) after an admin creates an OAuth application registry entry (System OAuth > Application Registry), but the authorize and token endpoints are per instance (`https://<instance>.service-now.com/oauth_auth.do` and `/oauth_token.do`) and the `apps` framework (0.0.1-beta.83) only accepts static endpoint URLs, so `oauth2` cannot be declared yet. This is a limit of the `apps` framework (`provider.d.ts` types `authorizationUrl` and `tokenUrl` as static strings), owned by the Executor apps framework team; it needs a per-connection endpoint feature. Instances that have disabled basic auth for REST cannot be connected until it can.
- Instances on a custom domain (not `*.service-now.com`) are not supported.
- Attachment upload is text only; binary uploads and downloads are not offered.
- Nothing was called against a real instance; checks were typecheck and deploy only.
- The `schema` tool lists columns defined directly on the table; inherited columns live on parent tables.
- The icon is the ring from the ServiceNow logo, taken from the logo SVG on Wikimedia Commons (https://commons.wikimedia.org/wiki/File:ServiceNow_logo.svg); Simple Icons has no ServiceNow entry and servicenow.com's brand page returns 403 to automated fetches, so the vendor-hosted SVG could not be downloaded. The Commons file is the widely used copy of the official ring mark; replace it with the press-kit SVG when available.
