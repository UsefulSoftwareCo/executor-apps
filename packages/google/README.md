# Google

Every linked Google account across Google's productivity APIs, in two layers:

- **Curated tools** at the top level, shaped for agents after [gogcli](https://github.com/openclaw/gogcli)'s typed tool set. Reads span every linked account at once (the app's requirement is `google.many()`) unless `account` names one by address, and each result says which account it came from. `search` looks through mail, Drive, calendar events and contacts in one call; `gmail.search`/`readThread`/`readMessage`/`labels`/`attachment` return decoded text instead of MIME, and `send`/`draft` take plain fields and handle replies (thread, `Re:` subject, `In-Reply-To`, reply-all); `gmail.modify` archives, marks read, stars, trashes and labels by name; `calendar.agenda` merges every shown calendar of every account and lists shared meetings once, `calendar.freeBusy` merges busy time across accounts and proposes free slots within working hours, and `createEvent`/`respond` take plain fields (with a Meet link on request); `drive.search` takes plain words or Drive query syntax and `drive.read` returns any file as text (Docs as Markdown, Sheets as CSV); `sheets.read`/`append`/`write`; `contacts.search` covers saved contacts, other contacts and the Workspace directory; `tasks.list`/`add`/`complete` cover every list. Their code is `curated.ts` (`accounts` and `search`) and `tools/`, copied from `shared/google-tools` by `node scripts/google-vendor.ts`; the single-product packages carry the same tools for their product.
- **The complete APIs** under `api`: Gmail (`api.gmail`, 85 tools), Google Calendar (`api.calendar`, 38), Google Drive (`api.drive`, 66), Google Sheets (`api.sheets`, 17), Google Docs (`api.docs`, 17), Google Slides (`api.slides`, 19), Google Forms (`api.forms`, 9), Google Tasks (`api.tasks`, 14), Google Contacts through the People API (`api.contacts`, 24), Google Meet (`api.meet`, 24) and Google Photos (`api.photos.library`, 12; `api.photos.picker`, 4): 329 tools, each taking an `accountId` from the top-level `accounts` tool.

Every mutation in both layers asks for approval. It is the all-in-one alternative to the single-product packages (`gmail`, `google-calendar`, `google-drive`, `google-sheets`, `google-docs`, `google-slides`, `google-forms`, `google-tasks`, `google-contacts`, `google-meet`, `google-photos`), with one sign-in per account instead of one per product.

## Interface

The curated tools call Google's REST APIs directly. Under `api`, nothing is new: `products/` holds copies of the single-product packages' sources, written by `node scripts/google-vendor.ts` (`--check` reports stale copies), because a catalog package must contain all of its own files. Edit the original package and rerun the script. The OpenAPI products use the same documents as their packages: APIs.guru's unofficial conversions of Google's Discovery documents for Sheets, Forms and Tasks (fetched live from `https://api.apis.guru/v2/specs/googleapis.com/<api>/<version>/openapi.json`), and checked-in conversions of Google's own Discovery documents for Gmail, Calendar, Drive, People and Photos (see those packages' READMEs). Docs, Slides and Meet are the hand-written tools of `google-docs`, `google-slides` and `google-meet` (each package's `tools.ts`). Each product keeps its package's known gaps.

## Auth

OAuth 2.0, discovered from `https://accounts.google.com`, with `access_type=offline` and `prompt=consent` so Google returns a refresh token. On Executor Cloud the connect page can use the hosted "Executor for Google" client, because every scope requested is on its allowlist. Otherwise create a "Web application" OAuth client in Google Cloud (Google Auth Platform > Clients), enable the Gmail, Calendar, Drive, Sheets, Docs, Slides, Forms, Tasks, People, Meet REST, Photos Library and Photos Picker APIs, add the redirect URI shown on the connect page (`/api/oauth/callback` on the Executor origin) and paste the client ID and secret into the connect page. Scopes: `openid`, `email`, `profile`, `https://mail.google.com/`, `gmail.settings.basic`, `calendar`, `drive`, `spreadsheets`, `documents`, `presentations`, `forms.body`, `forms.responses.readonly`, `tasks`, `contacts`, `contacts.other.readonly`, `directory.readonly`, `meetings.space.created`, `meetings.space.readonly`, `meetings.space.settings`, `photoslibrary.appendonly`, `photoslibrary.readonly.appcreateddata`, `photoslibrary.edit.appcreateddata` and `photospicker.mediaitems.readonly`. Gmail's and Drive's are restricted scopes: a self-made client outside its test users needs Google's restricted-scope verification. The health check reads the Gmail profile (`users/me/profile`) for the account's address; the curated tools read it from `oauth2/v3/userinfo`, cached per account for a day.

## Known gaps

- Left out because Executor for Google's scope allowlist does not include their scopes, and requesting them would stop Executor Cloud from offering its hosted client: Google Chat (`chat.*` scopes; use `google-chat`), Google Analytics (`analytics.*`; use `google-analytics`) and Google Ads (`adwords`, plus a developer token; use `google-ads`). Google Maps and Places take an API key rather than a user's OAuth token; use `google-maps`.
- Search Console, BigQuery, YouTube and Workspace Admin are not part of Google Super and have their own packages.
- Every gap listed in the single-product packages' READMEs applies here, such as Gmail's permanent-delete and delegation tools, which need scopes not requested.
- The curated tools leave out what gogcli gates hardest: permanent deletion, and sending with attachments (drafts and sends carry a text or HTML body only). Both remain possible through `api.gmail`.
