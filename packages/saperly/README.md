# Saperly

Saperly is a phone carrier for AI agents: provision phone numbers, place and manage voice calls (end, transfer, recordings, transcripts), send SMS, manage connections, voices and custom voices, record consent, get pricing quotes and read usage. This package exposes the data-plane operations of the API. The workspace/dashboard routes in the same document (members, invitations, workspace tokens, audit events) are included as published.

Interface: OpenAPI, loaded live from the vendor's own document at https://saperly.com/openapi-bundled.json (server https://api.saperly.com). Saperly also offers an MCP server (https://api.saperly.com/mcp, Streamable HTTP); the OpenAPI document is used here because it covers the full API.

Auth: API key. Create a scoped key in the Saperly dashboard (https://saperly.com, Keys). Keys are bearer credentials prefixed `sap_sk_live_...` (see https://saperly.com/docs/quickstart); paste it as the API key and it is sent as `Authorization: Bearer` to api.saperly.com. The vendor documents no test-mode key format or sandbox host. A key needs the scopes for the tools you use; a key with the `admin` scope (`keys:admin`) can also mint child keys via `POST /api-tokens`, bounded by its own grant. OAuth is offered by Saperly only on its MCP surface (dynamic client registration at https://saperly.com/api/auth/mcp/register); this OpenAPI package does not use it, and the REST API is authenticated with API keys.

Known gaps: the document declares no security schemes, so bearer auth is applied to every operation by configuration. All mutations require approval. The health check calls `GET /usage`. The `/workspaces/{slug}/...` routes (members, invitations, workspace api-tokens, webhooks, audit events) are dashboard/management routes; the vendor docs describe the `sap_sk` key as the agent credential and only some of them document admin-scoped key access, so these tools may return 401/403 for a key without sufficient scope. They were not called with real credentials.
