# ComPDF

Converts, edits, secures and parses PDFs with the ComPDF cloud API: PDF to Word, Excel, PowerPoint, HTML, RTF, CSV, OFD, text, JSON, Markdown, images and editable PDF; Word, Excel, PowerPoint, HTML, RTF, CSV, text and images to PDF; OCR conversion of images to Word, Excel, PowerPoint, RTF, text, HTML, JSON and CSV; merge, split, extract, delete, rotate and insert pages; compare two PDFs; encrypt, decrypt, add and remove watermarks, compress and convert to PDF/A, PDF/X, PDF/E or PDF/UA; PDF generation from HTML or templates; AI document parsing and field extraction; task list and close; account balance.

**Interface:** custom tools written with `fetch` against the official API at `https://api-server.compdf.com/server/v2` (`https://api-server.compdf.cn/server/v2` for mainland China accounts), following https://www.compdf.com/guides/api-reference/v2/overview. ComPDF publishes no OpenAPI document. ComPDFKit's official Apache-2.0 repository https://github.com/ComPDFKit/compdf-mcp ships a self-hosted MCP server (it runs on your own machine, default 127.0.0.1:8000, and is not a remote MCP endpoint), so the 47 tools are hand-written; the endpoint paths and field names come from the official parameter snapshot in that repository, which is generated from the API reference. Processing endpoints run in synchronous mode (multipart upload), which the vendor recommends for single files up to 10 MB (a request is limited to 50 MB). Each returns JSON with the output link in `data.downloadUrl` (`data` is an array with a `downloadUrl` per result for merge and other multi-file results); links are deleted at 24:00 the following day. HTTP 200 does not mean success, so check the top-level `code`. Error messages are requested in English (`language=1`); the vendor default is Chinese for some endpoints. Files are passed to tools as `{ fileName, contentBase64 }` or `{ fileName, url }`. All processing tools and `tasks.close` require approval.

**Auth:** API key (the project's Public Key), sent as the `x-api-key` header. Create one in the ComPDF API console under API Keys (https://api.compdf.com/). The optional `region` field selects the endpoint: leave it empty or `global` for api-server.compdf.com, or `china` for accounts created on the mainland China site (api-server.compdf.cn). The older v1 flow that exchanges a public and secret key for a bearer token is not used. No OAuth.

**Icon:** ComPDF has no separate product mark; its website, API console and GitHub organization all use the same two-square "C" logo, so that mark (the GitHub avatar, background removed to transparent) is the product mark. ComPDF publishes no SVG, and the only other official asset is a wordmark lockup and a 32px favicon.

**Known gaps:** asynchronous (`processAsync`) and pre-signed URL (`presignedUrl`) modes are not exposed, so use files within the sync limits above. The `url` file source relies on the Executor runtime allowing that host; use `contentBase64` otherwise. Not verified against a live key.
