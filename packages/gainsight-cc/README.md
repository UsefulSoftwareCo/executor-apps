# Gainsight CC

Covers Gainsight Customer Communities (formerly inSided): topics, questions, articles, ideas, conversations, product updates, categories, replies and moderation, user accounts, roles, profile fields and badges, community events, search and external content indexing, and gamification, 344 tools in all (mutations, 245 in the Community API alone, require approval). Tools are mounted under five keys: `community` (291), `user` (19), `events` (24), `search` (5), `gamification` (5).

Interface: OpenAPI 3.0, Gainsight's five official documents served by every region's API host and rendered at https://api2-us-west-2.insided.com/docs/ (`/v2/swagger.json`, `/api1/swagger.json`, `/events/swagger.json`, `/search/swagger.json`, `/gamification/swagger.json`). The documents are region independent, so each account's own `https://api2-<region>.insided.com` host is the base URL and credentials are only ever sent there. The Community API document is bundled as `community.json` because the published one contains empty arrays (`[]`) where objects are required, which the generator rejects; it is otherwise unchanged and those spots are `{}`.

Auth: one method, API client credentials. In your community's Control environment open Integrations > API, create credentials, and copy the client ID and secret; the page also shows your API base URL, whose `api2-<region>` part is the region (for example `eu-west-1` or `us-west-2`). When connecting, enter the region, client ID and secret. Executor exchanges them for a bearer token at `https://api2-<region>.insided.com/oauth2/token` (client credentials grant, scope `read write`, token valid two hours) and renews it as it expires. The grant is performed in code rather than with the framework's `oauth2` method because the token endpoint depends on the region. There is no authorization-code flow.

Known gaps: Gainsight CS, PX and Skilljar are separate products with separate APIs and are not included. If the credentials were created without write access, mutating tools fail.
