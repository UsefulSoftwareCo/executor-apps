# BoloForms

BoloForms' eSignature product (BoloSign): list, void and send reminders on documents, send PDF templates or form templates out for signing (up to 100 recipients per request), and read template respondents and form responses. This covers all six endpoints in the vendor's reference.

**Interface:** hand-written tools over the official BoloSign REST API (`https://sapi.boloforms.com/signature`), following the reference at https://bolosign-developer-docs.readme.io/ (section "BoloForms Signature API"). Tools: `documents.list` (`GET /get-documents`), `documents.void` (`POST /void-document`), `documents.sendReminder` (`POST /send-reminder`), `signing.sendPdfTemplate` and `signing.sendFormTemplate` (`POST /pdf-template-lambda` with `signingType` `PDF_TEMPLATE` or `FORM_TEMPLATE`), `templates.respondents` (`GET /get-template-respondent`) and `forms.responses` (`GET /get-form-responses`). The void, reminder and two send tools require approval. Methods, paths and fields were confirmed on each reference page's embedded OpenAPI definition (fetched as `https://bolosign-developer-docs.readme.io/reference/<operation>.md`) and the guides at https://signature-docs.boloforms.com.

**Why not an OpenAPI package:** each readme.io reference page embeds a fragment of the OpenAPI definition for just its own operation, and the portal serves no combined spec: `/openapi.json`, `/swagger.json` and `/openapi` on the portal return 404, `llms.txt` links only the per-page markdown, and integrations.sh lists none. There is no stable public URL for a full spec, so the tools are written by hand against those pages. BoloForms offers no MCP server or GraphQL API.

**Auth:** API key plus workspace id. In BoloSign open Settings, API Key, Generate API Key (https://signature-docs.boloforms.com/api-guides/key-generation). The key is sent as the `x-api-key` header to `sapi.boloforms.com`; the workspace id (a UUID) is sent as the `workspaceid` header on `get-documents`, which is also the health check. BoloForms offers no OAuth.

**Known gaps:** template creation, document download, webhook management and embedding are not part of the REST reference (webhooks and embed have documentation pages only). The reference spec for `sendPdfTemplate` requires `roleTitle` per receiver and does not list `roleColour`, while the signing guide says `roleColour` (a hex code) is necessary; the tool requires both. Document ids come from the dashboard URLs or from `documents.list`.
