# CommCare

Reads data from a CommCare HQ project space: applications (modules, forms, questions, case schemas), cases, form submissions, mobile workers, web users, groups, locations and location types, lookup tables and rows, configurable reports and their data, messaging (SMS/email) events, and the identity and project spaces of the API key's owner. All 25 tools are read-only, so none needs approval.

**Interface:** custom tools written with `fetch` against the official CommCare HQ REST APIs at `https://www.commcarehq.org/a/<domain>/api/...`, using the versions the current docs list: Case Data API v2 (`case/v2/`, cursor pagination), Location API v2, Location Types v1, Application Structure v1, List Forms / Form Data v1, mobile workers, web users and groups v1, lookup tables v1, configurable reports v1, messaging events v1, identity v1 and user domains v1. CommCare publishes no OpenAPI document or remote MCP server. Source: https://commcare-hq.readthedocs.io/api/index.html (each endpoint's own page there). Filter names were taken from those pages. Case v2 and messaging events paginate by following the `next` link; pass it back as `next` (it is only accepted when it points at this project space's endpoint).

**Auth:** API key. The account needs three fields: the CommCare username (email), an API key, and the project space (domain) name. Create the key at https://www.commcarehq.org/account/api_keys/ (My Account Settings, API Keys); it is sent as `Authorization: ApiKey <username>:<key>` as described on the API Authentication section of https://dimagi.atlassian.net/wiki/spaces/commcarepublic/pages/2279637003/CommCare+API+Overview . Keys can be restricted to IP addresses, so allow the Executor host's address. The CommCare API docs require a Standard plan or above. CommCare has no user-created OAuth apps for this API, so only the key is offered. Tools need the matching CommCare permissions (Edit Data, Edit Mobile Workers, Edit Web Users, Edit Apps, View Data). Only `www.commcarehq.org` is supported; the India and EU CommCare servers use other hosts and the account has no host field.

**Known gaps:** no write APIs are implemented (case create/update, form submission, mobile worker create/edit, web user invitations, bulk uploads, lookup table edits); adding them would need `always()` approvals. Form attachments, DET exports, OTA restore and bulk case fetch are not exposed. Lookup table rows cannot be filtered by table because the docs list no filter for it. Not exercised against a live project because no credentials were used.
