# Addepar

Wealth-management data in Addepar: portfolio queries and saved views, asynchronous export jobs, entities, positions, groups and group types, attributes, transactions, benchmarks, snapshots, target allocations, reports, files (metadata), users, teams, roles, contacts and the audit trail. 134 tools in 17 groups.

**Interface:** custom tools written with `fetch` against the official REST API (JSON:API) at `https://<subdomain>.addepar.com/api/v1`, following the developer documentation at https://developers.addepar.com/llms.txt. Addepar publishes no OpenAPI document (its reference pages are served only to browsers), so the routes were taken from the per-resource guides. Each tool takes the path `id` where the route has one, `params` for query-string parameters (`page[limit]`, `page[after]`, `filter[...]`) and `body` for the JSON:API request document. Reads and query-style POSTs (portfolio query, searches) run without approval; every other write needs approval.

**Auth:** API key, sent as HTTP Basic with the `Addepar-Firm` header. Fill in the firm subdomain (the `<subdomain>` of your `<subdomain>.addepar.com` login URL), the numeric firm ID, and the key and secret. Create the key in Firm Administration > Admin Tools > API Access Key (the user needs "API Access: Create, edit, and delete" first); the secret is shown once. The key has exactly the permissions and portfolio access of the user who created it, so use a dedicated service user. Addepar also supports OAuth 2.0, but client credentials are issued by Addepar to partner applications (redirect URIs, terms and privacy URLs are registered with Addepar) and there is no self-service registration, so OAuth is not offered.

**Known gaps:** file upload and download, and the zipped generated-report download, are not exposed (multipart or binary). Derivatives, fees and billing, payout rules, report schedules, constituent attributes, benchmark associations, pricing datasets and valuation events are not exposed. Job downloads return JSON only when the job was created with `output_type` JSON; other formats come back as text. Requests go to the firm's own host, so only production (`<subdomain>.addepar.com`) accounts are covered, not `clientdev` or sandbox hosts. Not verified against a live firm.
