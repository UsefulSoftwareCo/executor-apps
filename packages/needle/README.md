# Needle

Manage Needle (managed RAG) collections, files and connectors, and run semantic search over your indexed documents: list, create and inspect collections, list/add/remove collection files, search a collection, get signed file upload and download URLs and list connectors.

**Interface:** hand-written tools over the documented Needle REST API (`https://needle.app/api/v1`; reference at https://docs.needle.app/docs/api-reference/needle-api/). Needle publishes no OpenAPI document (the only one is a third-party Jentic conversion, not used). Endpoint paths and payloads were taken from Needle's official TypeScript SDK @needle-ai/needle 1.4.2 (https://github.com/needle-ai/needle-typescript). The SDK sends search to `search.needle.app`, but that host returned a 301 to a not-found page when probed, so search goes to `needle.app/api/v1/collections/{id}/search` (which answers 401 without a key); it is unconfirmed with a real key. Needle also offers an official remote MCP server (`https://mcp.needle.app/mcp`, `Authorization: Bearer <key>` per the needle-mcp README) but it exposes only a handful of tools, so the REST API is wrapped instead. The mutations (`createCollection`, `addFilesToCollection`, `deleteCollectionFiles`) require approval.

**Auth:** API key. Create one in your Needle account settings at https://needle.app/settings. It is sent as `Authorization: Bearer <key>`, which is what the official needle-mcp README and the live API (probed with a fake key) expect; the SDK 1.4.2 bundle sends `x-api-key` and the live server rejects that, so the SDK and its docs page are stale on this point. The live 401 also mentions OAuth access tokens (`ndl_oat_...`); no vendor document describing user-created OAuth apps was found, so an oauth2 method is not offered (unconfirmed).

**Icon:** the Needle mark from needle.app (`/images/needle-icon-25-11.svg`).

**Known gaps:** the local-folder connector endpoints and other connector types (Google, Slack, GitHub and so on, which need OAuth done in the Needle UI) are not wrapped; only listing connectors. Web connector creation was removed: the SDK has no such call and its POST contract could not be confirmed from vendor docs. `listCollections` has no paging (the SDK's listing does). `createCollection.model`, `getFileUploadUrls` content types and `deleteCollectionFiles.file_ids` (1-100) are validated in the handlers because the schema builders have no enum or length bounds. Needle's endpoints returned HTTP 429 to the authoring probe, so the MCP server was not probed and the REST routes were not exercised with a real key (only fake-key 401 probes).
