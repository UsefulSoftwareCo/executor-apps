# SafetyCulture

SafetyCulture (rebranded Mitti, "Mitti by SafetyCulture") covers inspections, templates, actions, issues, assets, sites (directory), users and groups, training, documents, companies, credentials, Heads Up announcements, data feeds and webhooks: 416 tools, 254 of them mutations (each needs approval).

**Interface:** OpenAPI. SafetyCulture publishes no combined OpenAPI file; every endpoint page on https://developer.mitti.com/reference/ embeds its official OpenAPI 3.1 definition. `openapi.json` is those definitions, merged by `fetch-openapi.mjs` (paths and components unioned; the script fails on conflicting operations or components). The top-level `info` block and the `servers` entry (`https://api.safetyculture.io`) are synthesized by the script, not published by the vendor; requests actually go to `https://api.mitti.com` (set in `openapi.ts`; the legacy `api.safetyculture.io` also works).

To regenerate the snapshot, run `node packages/safetyculture/fetch-openapi.mjs` (it reads the page index at https://developer.mitti.com/llms.txt, sends a browser-like User-Agent, and writes `openapi.json`). The portal sits behind a Cloudflare challenge that occasionally blocks a page; the script retries, and re-running is safe.

**Page accounting (as of 2026-10-12):** the index lists 461 reference pages. 416 carry an OpenAPI definition with one operation each, giving 416 operations. The other 45 are section and guide pages (introduction, use cases, bulk user operations, group overviews such as Users, Roles, Webhooks and so on) with no definition, plus three pages that duplicate operations already merged from other pages: `feedservice_feeddocumenttypes` and `feedservice_feeduserdocuments` (credential data feeds, also reachable under `/credentials/v1/feed/...`) and `traininganalyticsservice_getslidestatistics-1`. Pages whose definition sits in a four-backtick code fence (the user upsert endpoints) are included.

**Auth:** API token (`apiKey`), sent as `Authorization: Bearer <token>`. Create a user API token or a service user token in the Mitti web app (https://help.mitti.com/en-US/000007/ for user tokens, https://help.mitti.com/en-US/005096/ for service users). The API needs a Premium or Enterprise plan. No OAuth is documented for the public API as of 2026-10-12; the Apps API (private apps and installations) authenticates with the same bearer API token.

**Required token permissions:** the account health check calls `GET /share/connections`, which requires the "Platform management: Groups" permission. A token whose role lacks it fails the health check with a 403 that looks like a bad key. When creating the token (or the service user's role), grant at least "Platform management: Groups", plus the permission sets for the areas you want to use (for example Inspections, Templates, Actions, Issues, Assets, "Platform management: Users", Training). Each endpoint lists its required permissions on its reference page; a missing one returns 403 for that tool only.

**Gaps:** the remote MCP server (`https://mcp.mitti.com/mcp`) is Early Access, authenticates with OAuth 2.0 browser sign-in, and is read-only unless an administrator grants the "MCP: Write" permission. Because the official OpenAPI is preferred and OAuth sign-in does not fit this package, it is not mounted. Binary file downloads and webhook event payloads are not covered.
