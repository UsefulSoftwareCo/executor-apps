# FreshBooks

Invoices, clients, estimates, expenses and expense categories, items, payments, credit notes, bills, bill payments, bill vendors, other income, taxes, three accounting reports, projects, time entries and services in FreshBooks.

**Interface:** hand-written tools over the documented REST API (`https://api.freshbooks.com`, reference at https://www.freshbooks.com/api/). FreshBooks publishes no OpenAPI document, no GraphQL API and no remote MCP server, so a generic table (`operations.ts`) wraps the documented list/get/create/update endpoints. Each tool takes its path ids (`account_id` or `business_id`, plus `id`), a `query` object for filters and paging, and a JSON `body` for writes (wrapped in the object's singular name, e.g. `{"invoice": {...}}`). Every non-GET operation requires approval. Call `identity.getMe` first to find the `account_id` (accounting) and `business_id` (projects, time tracking).

**Auth:** OAuth 2.0 only; FreshBooks has no personal API keys. Create an app in the FreshBooks developer portal (https://my.freshbooks.com/#/developer) and add Executor's redirect URI to it (HTTPS, no query string). Enter the app's client ID and secret when connecting. The vendor's curl examples send JSON token requests (the docs never state the encoding), so the package sets `tokenRequestFormat: "json"`; this has not been tested against a live account. Refresh tokens are single-use and only one is valid per user per app: Executor stores the rotated refresh token returned by each refresh. The host does not send `redirect_uri` on refresh (the vendor's sample lists it but does not say it is required). Scopes requested are `user:profile:read`, `user:business:read`, `user:reports:read`, and `user:<object>:read` / `user:<object>:write` for invoices, clients, estimates, expenses, payments, credit_notes, bills, bill_payments, bill_vendors, billable_items, taxes, other_income, projects and time_entries. FreshBooks' scopes page (https://www.freshbooks.com/api/scopes) is the source of truth; it names no `profile:write` or `business:write`, so those are not requested.
**Icon:** the "f" mark from FreshBooks' own `mask-icon.svg` (https://www.freshbooks.com/mask-icon.svg), filled in brand blue; it is not in Simple Icons.

**Known gaps:** body and filter schemas are free-form JSON, so rely on the vendor reference. Retainers, online payments, teams, notifications, webhooks, project services and the less common reports are not wrapped. Paths were checked against the vendor's per-resource docs pages, but nothing was run against a live account. Unverified: credit notes (`/credit_notes/credit_notes`; no docs page found, tool descriptions say so). Not wrapped: journal entries, profit and loss and invoice share links (their documented endpoints use `/accounting/businesses/{business_uuid}/...`, a uuid this package does not obtain, or are not documented), and service updates (only service rates are documented). Deletion is a soft delete (`PUT` with `vis_state: 1`) for most accounting resources; only taxes, other income, projects and time entries have a real DELETE. Every request sends `Authorization` and `Accept`; the `Api-Version` header is not sent.
