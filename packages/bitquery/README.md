# Bitquery

Query indexed blockchain data (transfers, DEX trades, balances, blocks, smart-contract events) across 40+ chains, plus Bitquery's trading, tracing, AML and sanctions tooling.

- `mcp`: the official MCP server, `https://mcp.bitquery.io/mcp`. Per the vendor docs (https://docs.bitquery.io/docs/mcp/mcp-server/) it adds curated trading tools (per-trade rows, OHLC candles) and tracing tools (AML/KYC risk scoring, sanctions and OFAC screening, payment tracing, wallet clustering) that raw GraphQL does not provide; it is read-only server side. The vendor docs give conflicting tool counts ("a small set" vs. 173 in a screenshot caption); the real count is only visible with a signed-in account. Probed with `scripts/mcp-probe.ts`: 401 with a bearer challenge, OAuth 2.1 with dynamic client registration (`https://account.bitquery.io/oauth2/register`), scope `api`. Tools requiring approval: everything not annotated `readOnlyHint`.
- `graphql`: official V2 GraphQL API, `https://streaming.bitquery.io/graphql`. Tools are generated by introspection with your token (anonymous introspection is refused), so the count is not known offline. Only available to access-token accounts.
- Auth: either sign in with OAuth (MCP only), or paste an access token from https://account.bitquery.io (docs: https://docs.bitquery.io/docs/authorisation/how-to-generate/), sent as `Authorization: Bearer <token>` to both the MCP server and GraphQL.
- Known gaps: the legacy V1 API at `graphql.bitquery.io` and real-time subscriptions are not mounted. The GraphQL health check only confirms the token is accepted (no current-user query exists).
