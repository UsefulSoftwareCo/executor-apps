# Dynamics 365

Accounts, contacts, leads, opportunities, cases, quotes, orders, invoices, products, campaigns, activities, notes, users, teams and business units of one Dynamics 365 (Dataverse) environment, plus any other table, metadata discovery and FetchXML.

**Interface:** hand-written tools over the Dataverse Web API v9.2, `https://{org}.crm{N}.dynamics.com/api/data/v9.2/...` (OData v4). Microsoft publishes the API as per-environment CSDL `$metadata`, not as an OpenAPI document, so nothing can be compiled ahead of time. Each of 18 common tables has `list`, `get`, `create`, `update` and `delete`; `records.*` (list, get, fetchXml, create, update, upsert, delete) reaches any table, including custom ones, by entity set name; `metadata.listTables` and `metadata.listColumns` discover them; `actions.invoke` calls Dataverse actions; `whoAmI` returns the acting user. Mutations require approval. Docs: https://learn.microsoft.com/power-apps/developer/data-platform/webapi/overview. Nothing was exercised against a live environment.

**Auth:** Microsoft Entra client credentials (service principal). Dataverse scopes and hosts are per environment (`https://{org}.crm.dynamics.com/.default`), which a static `oauth2` declaration cannot express, so the grant is done in code at `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token`. Setup: register an app in Microsoft Entra ID with a client secret, then in the Power Platform admin center open the environment > Settings > Users + permissions > Application users, add the app and give it a security role. The connect form asks for the environment URL (for example `contoso.crm.dynamics.com`, from Power Platform admin center), the tenant ID, the client ID and the client secret. The token is sent only to that Dataverse host, which is validated against `{org}.crm{N}.dynamics.com`; the provider declares one `*.crm{N}.dynamics.com` host per regional suffix (crm, crm2 through crm25) because `*.` matches a single label. Entity set names, GUIDs, alternate keys and action paths are validated before being placed in a URL. The health check calls `GET /WhoAmI` (read-only).

**Official MCP server (not used):** Microsoft ships a built-in Dataverse MCP server per environment at `https://{org}.crm.dynamics.com/api/mcp` (and `/api/mcp_preview`). It is not used because its tool list is not documented publicly, its access is delegated (the Dynamics CRM `mcp.tools` permission, with each custom Entra client allow-listed per environment and no dynamic client registration), so it cannot be connected by a user-created app without per-environment admin setup, and it could not be probed without an org. The Web API tools above work with a plain application user. It is worth revisiting when an org is available to probe.

**Known gaps:** delegated user sign-in is not available;  only commercial-cloud hosts matching `*.crm*.dynamics.com` are accepted; GCC High, DoD and China (`dynamics.cn`, `microsoftdynamics.us`) environments are not. There is no delegated per-user OAuth sign-in, so actions run as the application user and are limited by its security role. Batch requests, file/image column upload and `@odata.nextLink` paging are not wrapped (page with `top` and filters). Dynamics 365 Finance and Operations and Business Central use different APIs and are not covered.
