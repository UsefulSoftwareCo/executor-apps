# SalesRobot

Runs LinkedIn outreach through SalesRobot: connected LinkedIn accounts, campaigns and sequences, prospects (add, import, pause, update, delete), inbox sync and messaging, daily quotas, schedules, blacklists, AI and smart-comment variables, voice and video personalization, LinkedIn profile, post and search-ID lookups, and job postings with applicants.

**Interface:** custom tools written with `fetch` against SalesRobot's REST API at `https://api.boomtechinc.com/api`, following the vendor's official Postman documentation at https://documenter.getpostman.com/view/10815846/2sB3BKE8Fb (linked from https://www.salesrobot.co/integrations). SalesRobot publishes no OpenAPI document and no MCP server. Almost every tool takes a `linkedinAccountUuid`; call `accounts.list` first. Mutations require approval.

**Auth:** API key, sent as the `X-API-KEY` header. Generate one at https://app.salesrobot.co/admin/settings?tab=apiKey. A LinkedIn account must be connected first (https://app.salesrobot.co/accounts, Add Account). SalesRobot has no OAuth. The vendor rate limit is 300 requests per minute. Verified against the public Postman collection JSON (https://documenter.gw.postman.com/api/collections/10815846/2sB3BKE8Fb), in which every request uses the `X-API-KEY` header on `https://api.boomtechinc.com/api`.

**Known gaps:** the inbound webhook endpoints (`https://app.salesrobot.co/public/webhooks/{webhookId}/...`, for example addProspect and replyToProspect) use a per-account webhook ID instead of the API key and are not exposed. The multipart video-avatar upload is not exposed. The older help-center article lists a `customeruuid` header for a few settings endpoints; the current Postman collection uses only `X-API-KEY`, which is what this package sends. Free-form bodies (campaign settings, sequence steps, quotas, schedule, job drafts) are passed as JSON objects following the field lists in the tool descriptions. The health check lists LinkedIn accounts and fails on any non-2xx response except 429.
