# Splunk

Splunk Enterprise and Splunk Cloud Platform. Covers running SPL searches (`search.oneshot`, asynchronous `search.jobs.*` with status, results, events, summary and control, `search.parse`), saved searches, reports and alerts (CRUD, dispatch, history, fired alerts), indexes, installed apps, dashboards, search macros, event types, tags, lookup files, data inputs (HEC tokens, monitors, TCP, UDP), users, roles, authentication tokens, the KV store (collections and records), server info and health, and a `request.get/post/delete` escape hatch for any other `/services` or `/servicesNS` REST endpoint.

**Interface:** hand-written tools over the Splunk Enterprise REST API (https://docs.splunk.com/Documentation/Splunk/latest/RESTREF/RESTprolog). Splunk publishes no OpenAPI document for this API, and the instance is per customer, so every tool is built by hand and sends `output_mode=json`. Tools accept optional `owner` and `app` to address the `/servicesNS/<owner>/<app>` namespace. (Splunk Observability Cloud and the Splunk Cloud Services API are separate products with separate credentials and are not covered; Splunk's MCP Server app is not used because it is an add-on installed per instance.)

**Auth:** an authentication token. In Splunk Web go to Settings > Tokens, create a token for a user with the needed capabilities, and enter it with your management host and port (for example `my-stack.splunkcloud.com:8089`). The token is sent as `Authorization: Bearer`. Splunk Enterprise needs token authentication enabled (Settings > Tokens > Token Settings). Splunk Cloud Platform exposes the management port only to allow-listed IPs; the Executor's egress IPs must be added to the `search-api` allow list. Splunk's REST API has no user-creatable OAuth, so OAuth is not offered.

**Gaps:** self-managed servers can use any domain, so the provider declares no fixed `hosts`: the token is held by app code and every request is built from the validated https management origin of the account (path-restricted for the raw `request.*` tools). Servers using a self-signed certificate on 8089 will fail TLS verification. Sending events through HTTP Event Collector (port 8088, separate token) is not covered, though HEC tokens can be managed. Mutations require approval, including `search.oneshot`, because SPL can write or delete data. The tools were typechecked and deployed but not called against a live Splunk instance.
