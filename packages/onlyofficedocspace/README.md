# ONLYOFFICE DocSpace

Rooms, files, folders, users, groups, sharing, security and portal settings on an ONLYOFFICE DocSpace portal (cloud or self-hosted), via the DocSpace backend REST API.

**Interface:** OpenAPI 3.0 (info.version 3.6.0), ONLYOFFICE's official DocSpace document at https://github.com/ONLYOFFICE/api.onlyoffice.com/blob/5c9331d6e0ebc7c97c7061b198951fe8306f2f75/openapi/docspace/docspace-backend.yaml (pinned to commit 5c9331d, 2025-12-18, the latest commit touching the file; no stable hosted URL exists, so it is vendored as `spec.ts`; regenerate with `python3 packages/onlyofficedocspace/generate.py <path to the yaml>`). Edits: the `{baseUrl}` server is replaced by a placeholder, and each operation's alternative security schemes (cookie, basic, JWT, API key, OAuth) are reduced to the API key. Calls are routed to the account's own portal; the placeholder origin is never contacted.

**Auth:** API key. In your portal open Developer Tools > API keys, create a key with the permissions you need, and enter your portal URL (https, e.g. `https://yourcompany.onlyoffice.com`) with the key. It is sent as `Authorization: Bearer <key>`, as documented in the vendor's API keys guide (site/docspace/api-backend/get-started/authentication/api-keys.md in the same repository). The connection check calls `GET /api/2.0/people/@self`.

**Gaps:** OAuth is not offered: DocSpace OAuth apps are registered on each portal (Developer Tools > OAuth 2.0), and the vendor's authorization-flow guide sends the token exchange to `{docspace_address}/oauth2/token`, so the endpoints are per portal, which the OAuth settings cannot express. The spec's `oauth.onlyoffice.com` URLs describe only the hosted ONLYOFFICE cloud. Portals are arbitrary hosts, so the provider declares no static `hosts` and the key is not host-restricted by the framework (same decision as other self-hosted packages: btcpayserver, gitea). Tool calls pin the allowed origin to the portal, and only https URLs are accepted. Mutations require approval. 497 tools.
