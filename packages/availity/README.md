# Availity

Availity healthcare clearinghouse: eligibility and benefits (X12 270/271), prior authorizations and referrals (X12 278), enhanced claim status (X12 276/277, summary and detail search), the payer list and per-payer validation rules.

**Interface:** hand-written tools over the Availity REST APIs at `https://api.availity.com/availity`. Availity publishes no downloadable OpenAPI document; the API reference lives in its developer portal (developer.availity.com), mostly behind login, so tools were written from the public API guide (`/blog/2025/3/25/availity-api-guide`), the HIPAA Transaction APIs page (`/blog/2025/3/25/hipaa-transactions`) and the Enhanced Claim Status page (`/blog/2025/3/25/enhanced-claim-status`). Tools: `payers.list`, `configurations.get`, `coverages.{create,search,get,delete}`, `serviceReviews.{create,search,get,update,delete}`, `claimStatus.{searchBy276,valueAdds277,summarySearch,detailSearch}` with a matching poll tool each, plus `api.get` and `api.send` for any other endpoint on your plan (Claim Statuses, Claims, Claim Attachments, Patient Cost Estimator, Remittance Data and so on). Every POST, PUT and DELETE needs approval. Nothing was exercised against a live account.

**Auth:** OAuth 2.0 client credentials. In the Availity developer portal create an account, register an application to get the API key (client ID) and secret (shown once, resettable), and subscribe it to an API plan. The Demo plan is approved automatically and returns canned, PHI-free responses (5 transactions per second, 500 per day); the Standard plan is contracted through your Availity Trading Partner Manager. Paste the key and secret on the connect page; Executor exchanges them at `https://api.availity.com/availity/v1/token` with `scope=hipaa`. Tokens last five minutes and there is no refresh token and no redirect URI. The health check calls `GET /v1/availity-payer-list?transactionType=270`, which carries no patient data.

**Known gaps:** most transactions are asynchronous, so submit and then poll with the matching get tool about every 2 seconds. Calls and polls all count against plan limits. The enhanced claim status paths (`/clmsmgmt/claim-status/claim-status/v1/status/...`) are taken from the documentation, which also shows an internal QA host in its samples, so the production prefix under `/availity` is unconfirmed; use `api.send` if it differs. Claim Statuses 1.0, Patient Cost Estimator, Claim Attachments and Remittance Data have no dedicated tools because their paths are not in public documentation; reach them through `api.get` and `api.send`.

**Icon:** the Availity mark (interlocked A, orange-to-yellow gradient) from the vendor's developer portal, `https://developer.availity.com/assets/images/icons/browser-icon.svg`. Visible on white and dark backgrounds.
