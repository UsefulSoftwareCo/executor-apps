# Coupa

Purchase orders, invoices, suppliers, requisitions, users, expense reports, contracts, ledger accounts and other reference data of one Coupa instance, plus any other Core API endpoint.

**Interface:** hand-written tools over the Coupa Core API, `https://{instance}/api/{resource}`, always requested as JSON (Coupa defaults to XML). Coupa publishes no public OpenAPI document: its developer docs (docs.coupa.com) are behind a JavaScript portal and the API reference is per instance, so nothing can be compiled ahead of time. Each of 19 common resources (purchase_orders, invoices, suppliers, requisitions, users, expense_reports, contracts, accounts, departments, commodities, currencies, exchange_rates, items, lookup_values, projects, addresses, business_groups, uoms, approvals) has `list` and `get`; `api.get` and `api.send` (POST/PUT/DELETE, approval required) reach every other endpoint and custom actions. Resource names and conventions (bracket filter operators such as `status[eq]`, `limit`/`offset` with at most 50 records per page, `fields`) come from Coupa's documentation as summarised by third-party guides; nothing was exercised against a live instance. Coupa's GraphQL API is not wrapped.

**Auth:** OAuth 2.0/OIDC client credentials, which is the only method Coupa still issues (API keys were retired). In Coupa, go to Setup > OAuth2/OpenID Connect Clients, create a client with the Client Credentials grant and select the scopes it needs (the full list for your instance is at `https://{instance}/oauth2/scopes`). The connect form asks for the instance host (for example `acme.coupahost.com`), the client ID, the client secret and the space-separated scopes to request, such as `core.common.read core.purchase_order.read core.invoice.read core.supplier.read`. The package exchanges them at `https://{instance}/oauth2/token` (client ID and secret sent in the form body with `grant_type=client_credentials` and `scope`, as in Coupa's setup guide) and sends the access token as a bearer token to that host only. A static `oauth2` declaration cannot express a per-instance token URL, so the grant is done in code. The health check exchanges a token, then calls `GET /api/users?limit=1&fields=["id"]` (read-only) and decodes nothing from the response.

**Known gaps:** only `*.coupahost.com` and `*.coupacloud.com` hosts are accepted; instances on a custom domain are not. No tokens are refreshed beyond re-requesting one (client credentials has no refresh token). Endpoints, and scopes such as `core.<object>.read` / `core.<object>.write`, depend on your instance and the client's grants; a 403 means a missing scope. Coupa Supplier Portal, CSP and Sourcing APIs are separate products and are not wrapped.

**Icon:** Coupa's starburst mark alone, extracted from the logo at https://en.wikipedia.org/wiki/File:Coupa_logo.svg (the wordmark is removed). The source is a non-free logo hosted on Wikipedia; coupa.com is behind a bot challenge and offers no brand-assets download, so replace it with the vendor's own asset if one is obtained. Visible on white and dark backgrounds.
