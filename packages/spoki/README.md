# Spoki

Spoki is an Italian platform built on WhatsApp's official APIs for marketing, sales, support and payments. This package covers sending templates and messages (text, interactive buttons, lists), contacts, lists, custom fields, tags, templates, campaigns, automations, tickets, media, channels, accounts, team roles and invitations, outgoing webhooks and partner endpoints: 92 tools.

**Interface:** custom tools written with `fetch` against Spoki's REST API at `https://api.spoki.com/api/1/`. Spoki publishes no OpenAPI document. Its reference is the Postman documentation at https://documenter.getpostman.com/view/21611004/UzBqnPvF; every path and method in this package was checked against that collection's JSON (the 186 requests it lists), including the channel, partners, external-webhooks, agencies, invitations, roles, reports/detailed and accounts/phone endpoints. Request bodies and list filters are passed as free-form JSON (`body`, `filters`; filter values should be scalars, arrays repeat the key and objects are sent as JSON), with the expected fields described in each tool's description. Every mutation requires approval, including `templates.clone`, which is a GET upstream but creates a draft template. `templates.delete` accepts `force_delete`.

**Official MCP server not used:** Spoki also publishes a remote MCP server at `https://mcp.spoki.com/v2/mcp` (Streamable HTTP; Official MCP Registry name `com.spoki/mcp`; docs at https://support.spoki.com/docs/integrazioni/spoki-mcp-auth-and-url/). It authenticates with Spoki-login OAuth (authorization server `https://web.spoki.com`, scope `spoki.mcp`, S256 PKCE, no registration endpoint) or the `X-Spoki-Api-Key` header. Its documented scope is contacts, lists, tags, automations, campaigns, templates, custom fields, tickets, operators and analytics, and its tool count depends on the plan and cannot be listed without a credential. This package uses REST because it also covers messages, channels, webhooks, team, media and partners, which that scope does not mention; the REST surface is a superset of the MCP's documented areas.

**Auth:** API key, sent as the `X-Spoki-Api-Key` header. Create it in the Spoki web app (app.spoki.it): Integrazioni, then Spoki MCP, then Request Api Key. The vendor documents the same `X-Spoki-Api-Key` header for the REST API and the MCP server, so this key is the one the REST API accepts; accounts without API access may not see the option. The REST API has no OAuth; only the MCP server offers Spoki-login OAuth. The health check lists accounts (read-only).

**Known gaps:** starting an automation through its webhook (`/wh/ap/<uuid>/`, single or bulk) is not exposed: it authenticates with a per-automation secret in the body instead of the API key and goes to the same host. The iframe embedding token endpoint, service-user roles and private-key endpoints, partner credit and software-vendor endpoints, and incoming webhook payload formats are also not wrapped. The Postman collection does not document most list query parameters, so `filters` is untyped. The collection also lists `auth/get_authentication_token`, which is not wrapped.
