# Cloudentity

Covers the Cloudentity (now SecureAuth Connect) Admin API for a tenant: workspaces (authorization servers), clients, identity pools and providers, scopes, claims, ACRs, policies, consents, MFA methods, gateways, organizations, audit events and more, 322 tools in all (176 mutations, each requiring approval).

Interface: Swagger 2.0, the vendor's own Admin API document at https://raw.githubusercontent.com/cloudentity/acp-client-go/b8f2a1b4bb591217fcf0be2e5951e9418edc0ba5/spec/admin.yaml (the spec the official Go client is generated from; Cloudentity does not host it on a docs URL). Its host and base path are placeholders, so each account's own tenant host and tenant ID are used (`https://<host>/api/admin/<tenantId>`), and credentials only go to that origin.

Auth: two methods, both asking for the tenant host (for example `acme.us.authz.cloudentity.io`) and tenant ID.
- Client credentials: in the Admin workspace, enable the client credentials grant, then create an application (Applications > Clients, a Service Application) and copy its client ID and secret. Enter the workspace the client lives in (`admin`). Executor exchanges them at `https://<host>/<tenantId>/<workspaceId>/oauth2/token` and renews the token as it expires. This is done in code because the token endpoint is on the tenant host, which the framework's `oauth2` method cannot express. The client authenticates with HTTP Basic (`client_secret_basic`, the OAuth default); if the client is configured for `client_secret_post`, set the optional `authMethod` field to `post`. The optional `scopes` field is a space-separated scope list sent as `scope`; the Admin API spec declares no scope names, so leave it empty to receive the scopes granted to the client (standard OAuth behavior), and set it if the server requires explicit scopes. The tenant ID is shown as "Tenant <id>" in the dashboard; the region is in the dashboard URL.
- Admin API access token: paste a token minted elsewhere.

Provider `hosts` cover `*.{us,eu,au,ca,uk,jp,sg,in}.authz.cloudentity.io` and `*.authz.cloudentity.io`. The framework only allows a wildcard for one leading label, so a broader pattern is not possible, and the region list is not verified against vendor docs (the vendor docs were unreachable); a tenant in an unlisted region needs the list extended. The earlier `*.connect.secureauth.com` entry was removed because its tenant URL shape could not be verified.

Known gaps: only the Admin API is covered, not the System, Developer, OAuth2 or identity APIs. The spec is pinned to a vendor repo commit. Which operations succeed depends on the scopes granted to the client. The health check calls `GET /api/admin/<tenantId>/servers` (the spec's list-workspaces operation); a 403 is treated as a valid token without that scope. No live call was made with credentials. The icon is the Cloudentity GitHub organization avatar, since no SVG logo or brand page could be reached.
