# Commerce Layer

Orders, line items, customers, SKUs, prices, stock, shipments, payments, promotions, markets and every other resource of the Commerce Layer Core API (1,273 tools, 332 of them mutations, which always ask for approval).

**Interface:** OpenAPI 3, from Commerce Layer's own public document at https://data.commercelayer.app/schemas/openapi.json (documented at https://docs.commercelayer.io/public-endpoints). The document lists a single server, `https://{your_organization_slug}.commercelayer.io/api`; each connected account is pinned to its own organization host, which the package reads from the `organization.slug` claim of the access token (not described in the vendor docs; taken from the published `@commercelayer/sdk` 8.0.2 source, which builds the host from that claim). `patches.json` works around two defects in the document so that all operations compile: it points at sub-schemas (`#/components/schemas/x/properties/data/...`) that the compiler does not accept, so each is lifted into its own component, and the `attachable` relationship of attachments lists four schemas the document never declares, so that `oneOf` is dropped.

**Auth:** OAuth client credentials (`oauth`). Create an "integration" API credential in the Commerce Layer dashboard (see https://docs.commercelayer.io/core/authentication/client-credentials), give it a role, and use its client id and client secret. Tokens are requested from `https://auth.commercelayer.io/oauth/token` (JSON body, client id and secret in the body) and last two hours; Executor renews them. What the credential may do is set by its role, not by scopes. There is no redirect URI, since this is a machine-to-machine grant.

**Known gaps:** the Metrics API (`/metrics`, https://data.commercelayer.app/schemas/metrics/openapi.json) and the Provisioning API (`provisioning.commercelayer.io`, its own credentials) are not mounted. Commerce Layer's official Core and Metrics MCP servers (`https://core-mcp.commercelayer.io/mcp`) use OAuth sign-in and are not mounted. Sales-channel (public client id only) credentials are not supported.
