# Kernel

Cloud browsers for AI agents with Kernel: create and manage browser sessions, control mouse, keyboard and screen, manage profiles, proxies, extensions, managed auth connections, apps, deployments, invocations and replays.

**Interface:** Kernel's official OpenAPI 3.1 document, https://api.onkernel.com/spec.json (the document the API reference pages at https://kernel.sh/docs are generated from), served from `https://api.onkernel.com`. It describes 128 paths and 184 operations; 177 are mounted. The 7 excluded operations are GET endpoints that return `text/event-stream`, which the tool runtime cannot consume: `/auth/connections/{id}/events`, `/browsers/{id_or_name}/fs/watch/{watch_id}/events`, `/browsers/{id_or_name}/logs/stream`, `/browsers/{id_or_name}/process/{process_id}/stdout/stream`, `/browsers/{id_or_name}/telemetry/stream`, `/deployments/{id}/events` and `/invocations/{id}/events`. The catalog target "Kernel MCP" is the same product. Kernel's hosted MCP server (https://mcp.onkernel.com/mcp, OAuth with dynamic client registration) is not mounted: each of its tools has a REST counterpart in the spec (`manage_browsers`, `manage_profiles`, `manage_browser_pools`, `manage_proxies`, `manage_extensions`, `manage_apps`, `manage_replays` map to the corresponding resource paths; `computer_action` to `/browsers/{id}/computer/*`; `execute_playwright_code` to `/browsers/{id}/playwright/execute`; `browser_repl` to `/browsers/{id}/repl`; `webmcp` to `/browsers/{id}/webmcp/tools` and `/webmcp/invoke`; `exec_command` to `/browsers/{id}/process/exec`; browser curl to `/browsers/{id}/curl`). The only MCP-only capability not covered is `search_docs` (documentation search; see https://kernel.sh/docs).

**Auth:** API key only, sent as a bearer token (`Authorization: Bearer <key>`). Create one as described in https://kernel.sh/docs/info/api-keys.md (org or project scoped). Kernel has no user-created OAuth apps for its REST API, so no OAuth is declared. The health check calls `GET /auth/context`.

**Approvals:** every non-read operation (creating or deleting browsers, computer actions, deployments, invocations, auth connections) asks for approval.

**Machine payments:** `POST /mpp/browsers` ("Buy a browser session with a machine payment") is declared with no security in the spec: it does not use the API key and instead takes an `Authorization: Payment` credential after a 402 challenge, so the call spends money outside the key's account. It is mounted and requires approval like every POST; review it before approving.

**Known gaps:** the 7 SSE streaming operations above are not mounted; only operations in the official spec are covered; streaming endpoints (SSE) and binary downloads depend on what the OpenAPI tool runtime supports. Some endpoints (audit log export destinations) require an Enterprise plan. No live call with a real key was made.
