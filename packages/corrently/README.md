# Corrently

Corrently by STROMDAO exposes German electricity data: GrünstromIndex (green power) and CO2 forecasts per ZIP code, best-hour and dispatch recommendations, market data, standard load profile tariffs, metering readings, wallet-style Stromkonto accounts, receipts (Quittung) and EV charging sessions (Easee, OCPP, OpenMeter).

Interface: OpenAPI 3, https://api.apis.guru/v2/specs/corrently.io/2.0.0/openapi.json. This is an APIs.guru-hosted copy of a STROMDAO document (APIs.guru records its origin as corrently.io/dist.yaml, which no longer resolves). It has 25 paths and 26 operations from 2020 and may lag the live API. It is a third-party mirror, kept because it is far more complete than the only spec the vendor still publishes: the narrower GrünstromIndex 1.0.0 document on SwaggerHub (https://api.swaggerhub.com/apis/corrently/grundfunktion/1.0.0), which has just 3 paths (`/v2.0/gsi/prediction`, `/v2.0/gsi/bestHour`, `/v2.0/gsi/pps`). Corrently's `https://api.corrently.io/v2.0/mcp/tools` is a plain 7-tool JSON listing, not an MCP protocol server (initialize returns 404), so it is not used.

Auth: access token (API key). Create one at https://console.corrently.io/ (an anonymous short-lived token or a registered one). It is sent as `Authorization: Bearer <token>`. No OAuth. The token is required here (minimum length 1), which is stricter than the vendor: Corrently also serves anonymous requests with a deprecation warning. The vendor does not validate tokens at all (a bogus Bearer token gets the same HTTP 200 as none; tokens only raise rate limits), so the health check only confirms the API is reachable, and a wrong key is accepted when connecting. No read-only endpoint that rejects bad tokens was found.

Known gaps: the spec lacks newer live endpoints, notably `/v2.0/switchboard/gsiCO2` (the vendor's CO2 prediction tool), the solar prediction tool and the CO2 offset (tree) calculation; mutations (receipts, Stromkonto, metering writes) need approval.
