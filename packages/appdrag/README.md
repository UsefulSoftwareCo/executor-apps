# AppDrag

Covers AppDrag's Cloud Backend for one project per account: SQL queries and statements against the project's Cloud Database, file and directory management in Cloud Backend storage, sending email, and calling the project's own API functions (GET, POST, PUT, PATCH, DELETE).

Interface: custom, hand-written tools. AppDrag publishes no OpenAPI document, GraphQL API or MCP server. The management commands (`CloudDBGetDataset`, `CloudDBExecuteRawQuery`, `DirectoryList`, `WriteTextFile`, `FileCopy`, `CloudAPISendEmail` and others) follow AppDrag's official `appdrag-cloudbackend` Node SDK (https://github.com/AppDrag/appdrag-cloudbackend), which posts them to `https://api.appdrag.com/CloudBackend.aspx`. Function calls use `https://<project name>.appdrag.com/api/<folder>/<function>`, as documented at https://support.appdrag.com/doc/Interacting-with-my-API-Functions.

Auth: API key. In https://prod.appdrag.com/cloudbackend.html open the project, choose API in the left menu, and copy the App ID (top left) and the API key (press the APIKey button), and note the project name (the subdomain of your `<project name>.appdrag.com` function URL). Enter all three when connecting; one account is one project. There is no OAuth.

Known gaps: the SDK is old and AppDrag does not publish a reference, so command names come from the SDK source. Reading a file's contents, binary uploads, newsletter commands and the dev/preprod environments are not exposed. Functions on a custom domain are not reachable; the `<project name>.appdrag.com` host is used. The vendor page does not name the body format for POST/PUT/PATCH/DELETE function calls, so the JSON body (with the API key as a body field) is an assumption, as are the shapes of management responses. `database.select` and `functions.get` require approval because AppDrag does not document `CloudDBGetDataset` as read-only and GET functions are user-defined and may have side effects. The health check only verifies reachability (an HTTP 2xx JSON reply to a storage-root listing); AppDrag publishes no response schema, so it does not prove the key is valid.
