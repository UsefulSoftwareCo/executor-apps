# Emelia

Emelia is a B2B prospecting tool: cold email campaigns, contact lists, mailbox providers, email warm-up, email finder and verification, LinkedIn outreach and webhooks.

## Interface

Two surfaces, both under one account, with the same raw `Authorization` key:

- GraphQL at `https://graphql.emelia.io/graphql` (docs: https://docs.emelia.io). Tools are generated by introspection at connect time under `graphql`; the schema needs an API key, so the count is unverified (an estimate of about 6 operations: account, campaigns list/add/remove contact, contact lists).
- A hand-written REST layer under `rest` for `https://api.emelia.io` (19 tools): email finder and verifier jobs, phone finder, email providers, webhooks, multichannel and LinkedIn campaigns, blacklist. Paths come from the docs.emelia.io endpoint pages; the docs site is JS-rendered and could not be fetched here, so request bodies for some write endpoints (webhooks, LinkedIn, blacklist) are best-effort and unexercised against a live key.

Emelia publishes no OpenAPI document and no MCP server. Every mutation (GraphQL and REST) requires approval.

## Auth

API key. Create one in Emelia under Settings, API keys, and paste it into the connect page. The key is sent as the raw `Authorization` header, without a `Bearer` prefix. Emelia does not offer OAuth.

## Known gaps

- The tool count could not be checked without a real account, because the schema requires authentication (unauthenticated requests get `UNAUTHENTICATED`). Verification covers typecheck and deploy only; the health check is unexercised against a live key.
- Legacy REST email-campaign contact endpoints (`/emails/campaign/contacts`) and REST list management are not mounted; GraphQL covers adding contacts to campaigns and lists.
- The health check checks only that `me` is non-null and surfaces the GraphQL `errors[0].message` on a bad key.
