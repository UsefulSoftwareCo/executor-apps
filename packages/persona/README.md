# Persona

Identity verification and fraud tooling from Persona: inquiries and inquiry templates, verifications, reports, accounts, cases, lists and list items, graph queries, transactions, devices, webhooks, API keys, and more (218 tools).

**Interface:** OpenAPI 3.1 from Persona's official repository, [persona-id/persona-openapi](https://github.com/persona-id/persona-openapi), pinned to commit `1da483e` (`2026-09-29/openapi-bundled.json`, API version `2026-09-29`) so the tool set cannot change underneath the package. The repo is generated by Persona's own persona-web publish pipeline. Every request sends `Persona-Version: 2026-09-29`; without it Persona would run the request on the API key's own version, which can differ between keys. All calls go to `https://api.withpersona.com/api/v1`.

**Auth:** API key (`apiKey`). Create one in the Persona Dashboard under API > API Keys; permissions are set under API > API Keys > Edit > Permissions. Keys are environment-specific: `persona_sandbox_...` keys only work against Sandbox and `persona_production_...` keys only against Production. Creating or editing keys in the Dashboard requires the Admin role or API Key permissions; the key used here only needs the API Key permissions (`api_key.read`/`api_key.write`) if you want the key-management tools to work. It is sent as `Authorization: Bearer <key>`. Persona's OAuth endpoints are for sharing resources between organizations (Connect), not for user-created apps, so OAuth is not offered. All mutations require approval.

**Known gaps:** the Privacy Pass auth scheme is not supported (one operation skipped). Webhook event payloads are not tools. Tools only see what the API key's permissions and payload filters allow.
