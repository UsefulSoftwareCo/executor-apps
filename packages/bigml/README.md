# BigML

BigML's machine learning platform: projects, data sources, datasets, samples, correlations, statistical tests, decision tree models, ensembles, clusters, anomaly detectors, association discovery, logistic and linear regression, deepnets, time series, topic models, PCA, fusions, OptiML, evaluations, single and batch predictions (centroids, anomaly scores, association sets, topic distributions, projections, forecasts), WhizzML scripts, libraries and executions, configurations and external connectors. 37 resource types, each with `list`, `get`, `create`, `update` and `delete` (185 tools; the official Python bindings define update and delete handlers for all 37 types). `list` filter values may be scalars, arrays (comma-joined) or objects (JSON).

**Interface:** hand-written tools over BigML's REST API at `https://bigml.io/andromeda` (documented at https://bigml.com/api). BigML publishes no OpenAPI document, GraphQL API or remote MCP server (checked: bigml.com/api is a JS-rendered reference only; the `bigmlcom` GitHub org has bindings in Python, Node, Java, R and others, plus a `raml-spec` repo that is only a fork of the RAML language spec, not a BigML API description). Every resource type lives at `/<type>` and `/<type>/<id>`; the resource list and the `andromeda` version segment were cross-checked against BigML's official Python bindings. `create` and `update` take an `args` object that is sent as the JSON body, so any BigML creation argument works; each `create` description names the required keys. Creation is asynchronous, so poll `get` until `status.code` is 5. Resource ids can be given bare or as `type/id`.

**Auth:** username plus API key (BigML has no OAuth). BigML sends both as `username` and `api_key` query parameters on every request; there is no header alternative. Find them under Account > API Key at https://bigml.com/account/apikey. Credentials go to `bigml.io` only. BigML embeds the live credentials in the `next` and `previous` pagination links of list responses; the tools strip them from results (`redact.ts`, splitting on both `&` and `;`, covered by `redact.test.ts`). Errors carry only the status and BigML's error body, never the request URL. Health check lists one project.

**Approvals:** every `create`, `update` and `delete` requires approval. Creating resources consumes BigML credits.

**Known gaps:** no local file upload (multipart sources); create a source from a remote URL or inline `data`. No downloads of binary artifacts (model PMML, dataset CSV exports). The EU/other regional domains and the `/dev` development mode are not exposed. BigML Organizations and Projects scoping can be passed through `args` (`project`, `organization`).

**Icon:** BigML's official "ML" ball mark (`bigml_version_light_ml.svg` from the logo kit linked on https://bigml.com/brand, https://static.bigml.com/static/images/brand_guidelines/BigML_logo_versions.zip). The brand page also offers full wordmark versions; the standalone mark is used. Simple Icons has no BigML entry.
