# SHOPLINE

Manage SHOPLINE e-commerce stores: products, variants, images, collections, inventory and locations, orders, drafts, refunds, fulfillments, returns, subscriptions, customers and groups, gift cards, discounts and price rules, marketing events, online store content (blogs, pages, themes, redirects), metafields, metaobjects, files, webhooks and SHOPLINE Payments reports.

**Interface:** hand-written tools over the official SHOPLINE Admin REST API (`https://{handle}.myshopline.com/admin/openapi/v20260901`, reference at https://developer.shopline.com/docs/admin-rest-api/). SHOPLINE publishes no downloadable OpenAPI document, so the 439 endpoints (method, path, scope and description) are listed in `endpoints.ts`, taken from the vendor's per-endpoint reference pages, and turned into tools at runtime. Tools are grouped by the reference's own sections (`order`, `customer`, `product`, `marketing`, `onlineStore`, ...). Each tool takes its path ids as strings, an optional `query` object for filters (list endpoints page with the `page_info` token from the `link` response header) and, for writes, a JSON `body`. Every write requires approval. The pinned version is `v20260901` (current stable).

**Auth:** Admin API access token plus the store handle (the `<handle>` in `<handle>.myshopline.com`). The token is issued when an app is authorized for a store: create a custom app in the SHOPLINE Partner Portal (https://developer.shopline.com/docs/apps/api-instructions-for-use/app-authorization), grant the access scopes you need (https://developer.shopline.com/docs/apps/api-instructions-for-use/access-scope), and authorize it on your store. The token is sent as a bearer token to `*.myshopline.com`. The account health check reads `/merchants/shop.json`, so the token needs the `read_store_information` scope. OAuth is not offered: SHOPLINE's flow uses non-standard parameters (`appKey`, `responseType`, `redirectUri`), a per-store host, an IP allow-list and an app-secret signature (`appkey`, `timestamp`, `sign` headers) on token creation and refresh, which the declarative OAuth settings cannot express. Tokens from that flow expire after 10 hours, so refresh them outside Executor.

**Known gaps:** the payment-app callback endpoints (`payments_apps/openapi`) are not wrapped, nor are the Admin GraphQL and Storefront APIs, whose schemas are only published in an interactive explorer. One reference page (product tags on the current store) has no readable endpoint and is omitted. Endpoints requiring "not private" scopes (selling plans, subscription contracts) only work for public apps.
