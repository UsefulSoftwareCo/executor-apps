# Moosend

Email marketing with Moosend: campaigns (create, update, clone, test, schedule, send, delete) and campaign reports, mailing lists and custom fields, segments and their criteria, senders, and subscribers (add, update, unsubscribe, remove). 47 tools, grouped by API area (`campaigns`, `lists`, `segments`, `subscribers`, `senders`).

**Interface:** hand-written tools over Moosend's official V3 REST API at `https://api.moosend.com/v3`. Moosend's V3 reference (the Apiary blueprint at https://moosendapp.docs.apiary.io/, which moosend.com/api points to via https://docs.moosend.com/api-documentation) documents no OpenAPI file and no MCP server, and `https://api.moosend.com/openapi.json` and `/swagger.json` return 404; docs.moosend.com is a JavaScript-rendered help center that could not be read here, so "none published" is based on the blueprint and those probes only. `routes.ts` is a table of every endpoint in that reference, cross-checked against the endpoint lists of Moosend's own API wrappers (https://github.com/moosend/api-wrappers-js), and `index.ts` turns each row into one tool. Request bodies are passed as a `body` JSON object. Responses are returned as the API sends them (`{ Code, Error, Context }`).

**Auth:** API key only; the V3 API has no OAuth. Find or generate it in your Moosend account settings (the API reference says "the respective section under the Settings Menu"; the exact menu path is not confirmed). The key is sent as the `apikey` query parameter to `api.moosend.com`, which is how Moosend expects it. The health check lists mailing lists.

**Notes and gaps:** every non-GET tool asks for approval. Request bodies are not typed because the reference documents them only as HTML. Endpoints, parameter names and paging were checked against the Apiary blueprint (fetched through jsapi.apiary.io) and the official wrappers. Note the vendor's own naming is inconsistent: the lists calls take `ShortBy`, while the campaigns-by-page call takes `SortBy` (the JS wrapper's `ShortBy` for campaigns is its typo). `Page` and `PageSize` on getSegmentSubscribers are not listed in the blueprint's parameters (it only says paging is required) and are unverified against a live account; they are optional and follow the paging names used by getSubscribers. newer endpoints (for example automations or transactional sending) are not covered. Responses are not schema-checked.
