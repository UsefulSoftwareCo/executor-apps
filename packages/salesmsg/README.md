# Salesmsg

Business texting with Salesmsg: contacts, conversations, messages, broadcasts (including recurring), tags, custom fields, saved replies, numbers, teams, keywords, triggers, attachments, analytics and more (414 tools, mutations require approval).

Interface: OpenAPI, loaded live from Salesmsg's own public API document, https://app.salesmessage.com/api/docs/salesmessage-public-api-v2.3.json (API base https://api.salesmessage.com/pub/v2.3). Two operations are skipped by the compiler: `POST /groups/create-integration-group` (its security requirement names an undeclared `bearerAuth` scheme, a spec error) and `GET /organization/call-queue-participants/{team?}` (the optional `?` path parameter is not a valid path). The OAuth token endpoints are not exposed as tools.

Auth:
- Personal access token: create one at https://app.salesmessage.com/settings/developer/access-tokens and paste it in. It is sent directly as a bearer token. Salesmsg's spec says a PAT "allows access to our API just like an OAuth token", and its personal-token refresh endpoint authenticates with the PAT as a bearer (it only extends the token's life), so the raw PAT is accepted as a bearer. This was not confirmed with a live token; a malformed bearer returns a 403 decode error, which shows the API reads the bearer as a JWT.
- OAuth: register an OAuth application at https://app.salesmessage.com/settings/developer/applications, add Executor's callback URL as the redirect URI, and enter the client ID and secret. Authorization goes to https://app.salesmessage.com/auth/oauth with space-separated scopes (for example `contacts:read`); tokens come from https://api.salesmessage.com/pub/v2.3/oauth/token. Requested scopes cover the read/write areas most tools use; admin-style scopes (agency organizations, role permissions, integrations, toll-free compliance) are not requested.

Known gaps: Salesmsg documents token refresh as `POST /pub/v2.3/oauth/token/refresh`, but the framework's oauth2 contract only takes a `tokenUrl`, so refresh uses `/oauth/token` with `grant_type=refresh_token`. Unauthenticated probes cannot tell whether that endpoint honors the refresh grant. Access tokens last about a year, so if refresh fails the user must reconnect. Also: the API is rate limited to 60 requests per minute. The health check calls `GET /users/me` and only verifies success, because its documented response has no stable identity fields. Unauthenticated validation was not possible; auth details come from Salesmsg's API document.
